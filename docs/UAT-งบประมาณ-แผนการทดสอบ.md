## 1. วัตถุประสงค์

1. ให้ผู้ใช้ยืนยันว่าขั้นตอนตั้งงบ ใช้งบ และดูคงเหลือ ตรงกับงานจริงของโรงพยาบาล
2. ตรวจว่าวงเงินถูกกันและตัดถูกต้อง ตามสถานะเอกสาร PR / PO / ใบตั้งเจ้าหนี้
3. ตรวจว่าเลือกแบบฟอร์มผิด หรือจับคู่มิติงบไม่ครบ แล้วระบบกันได้
4. เก็บหลักฐานผ่าน/ไม่ผ่าน สำหรับตัดสินใจ Go-Live

## 2. ขอบเขต

### อยู่ในขอบเขต

- ข้อมูลหลักงบประมาณ (แหล่งเงิน หน่วยงาน แผนปี แบบฟอร์ม หมวดงบ กลุ่มวัสดุ)
- คำของบหน่วยงาน 4 แบบฟอร์ม และการอนุมัติเข้าแผนประจำปี
- การใช้จ่ายผ่านใบขอซื้อ (PR) ใบสั่งซื้อ (PO) และใบตั้งเจ้าหนี้
- การจองงบ / ผูกพันงบ / ใช้จริง / คงเหลือ
- บทบาทหน่วยงาน งานงบประมาณ พัสดุ การเงิน
- หน้าสรุปและ Dashboard ที่เกี่ยวกับงบ

### อยู่นอกขอบเขตรอบนี้

- การตั้งค่าระบบบัญชีทั้งโรงพยาบาลที่ไม่เกี่ยวกับงบ
- การเชื่อม HIS / API รายได้
- การพิมพ์รายงานราชการฉบับสมบูรณ์นอกระบบ (ถ้ามีในเฟสถัดไป)
- Performance / Security penetration

## 3. สิ่งที่ต้องเข้าใจก่อนทดสอบ

ระบบมี 2 ช่วง ห้ามสลับลำดับ

| ช่วง | เอกสาร | ผลลัพธ์ |
|---|---|---|
| 1. ตั้งงบ | คำของบหน่วยงาน | ได้วงเงินจัดสรรในแผนประจำปี |
| 2. ใช้งบ | PR → PO → ตั้งเจ้าหนี้ | กันเงิน แล้วตัดเป็นใช้จริง |

สูตรตัดสินผลทุกเคสใช้จ่าย

```
คงเหลือ = งบจัดสรร − ใช้จริง − จอง PR − ผูกพัน PO
```

กติกาที่ผู้ทดสอบต้องจำ

- ยอดที่ใช้ได้ คือ **ยอดจัดสรร** ไม่ใช่ยอดที่ขอ
- ส่ง PR แล้วเงินถูกจอง ใบอื่นใช้วงเงินซ้ำไม่ได้
- ยืนยัน PO แล้วยอดย้ายจากจองเป็นผูกพัน
- โพสต์ใบตั้งเจ้าหนี้แล้วยอดกลายเป็นใช้จริง
- ระบบจับคู่วงเงินจาก **หน่วยงาน + แหล่งเงิน + หมวดงบ** และถ้าเป็นวัสดุต้องมี **กลุ่มวัสดุ**

## 4. ผู้เกี่ยวข้อง

| บทบาท | สิทธิ์ในระบบ | หน้าที่ตอน UAT |
|---|---|---|
| หน่วยงาน | Budget Request – Department / User | สร้างคำของบ สร้าง PR เช็คงบ |
| งานงบประมาณ | Budget Request – Budget Unit / Manager | ตรวจข้อมูลหลัก รับเรื่อง จัดสรร อนุมัติ/ตีกลับ |
| พัสดุ / จัดซื้อ | ผู้ใช้จัดซื้อ | ยืนยัน PO |
| การเงิน | ผู้ใช้บัญชี | ตั้งเจ้าหนี้ / โพสต์บิล |
| ผู้ประสาน UAT | — | คุมลำดับเคส บันทึกผล เปิดบั๊ก |
| IT | ผู้ดูแลระบบ | เตรียมฐาน บัญชีผู้ใช้ กู้ข้อมูลถ้าจำเป็น |

แนะนำบัญชีทดสอบแยกคนละบทบาท อย่างน้อย 4 user ห้ามใช้ admin คนเดียวกดครบทุกขั้น ถ้าต้องการพิสูจน์สิทธิ์

## 5. สภาพแวดล้อมและข้อมูลเตรียม

- ระบบ: Odoo 18 ฐาน `VPK-S1` (หรือฐานสำเนา UAT ที่ตกลง)
- ปีงบประมาณที่ใช้ทดสอบ: ปีปัจจุบันของโรงพยาบาล
- หน่วยงานทดสอบ: เลือก 1 แผนกจริงที่คุ้นเคย เช่น กลุ่มงานเภสัชกรรม หรือสำนักงาน
- แหล่งเงินทดสอบ: อย่างน้อย เงินบำรุง และอีก 1 แหล่ง
- แบบฟอร์มที่ต้องเห็นในเมนู มีแค่ 4 ใบ
  1. แบบฟอร์มตั้งงบวัสดุ
  2. แบบฟอร์มครุภัณฑ์
  3. แบบฟอร์ม ก่อสร้าง
  4. แบบฟอร์มโครงการ

ก่อนเริ่มรอบบันทึกผล ต้องมีข้อมูลหลักครบตามชุด A หากไม่ครบ ให้งานงบเตรียมก่อน ห้ามเริ่มชุด C

## 6. เกณฑ์เข้าทดสอบ / ออกจากทดสอบ

### เข้าทดสอบได้เมื่อ

- เมนูคำของบเหลือ 4 แบบฟอร์ม
- มีแผนงบประมาณประจำปีของปีที่ทดสอบ
- มีหน่วยงาน แหล่งเงิน หมวดงบ และกลุ่มวัสดุอย่างน้อย 1 ค่าต่อประเภท
- มีบัญชีผู้ใช้ครบบทบาท
- ผู้ทดสอบเข้าอบรมภาพรวมแล้ว (ใช้ไฟล์ PPT)

### ผ่านรอบ UAT เมื่อ

- เคสสำคัญ (ชุด A–D ในตารางด้านล่าง ที่ทำเครื่องหมาย P1) ผ่านทั้งหมด
- เคส P2 ไม่ผ่านได้ไม่เกินที่ทีมยอมรับ และมีแผนแก้ก่อน Go-Live
- ไม่มีบั๊กระดับ Blocker ค้าง เช่น อนุมัติแล้วไม่เข้าแผน หรือ PR ส่งได้ทั้งที่งบไม่พอ

### ระดับความรุนแรง

| ระดับ | ความหมาย | ตัวอย่าง |
|---|---|---|
| Blocker | ใช้งานหลักไม่ได้ | อนุมัติแล้วไม่มีวงเงิน, PR เกินงบแล้วยังส่งได้ |
| Major | ใช้งานได้แต่ผิดกติกาเงิน/สิทธิ์ | จองงบไม่ปลดเมื่อมี PO |
| Minor | ใช้ต่อได้ แต่สับสน | ชื่อเมนูไม่ตรง, ข้อความ error ภาษาไม่ชัด |
| Cosmetic | สวยงามเท่านั้น | สี ระยะห่าง ฟอนต์ |

## 7. ลำดับรอบทดสอบ (ห้ามข้าม)

ทำตามนี้ เพราะขั้นหลังใช้วงเงินที่ขั้นก่อนสร้างไว้

1. ชุด A ข้อมูลหลักและสิทธิ์
2. ชุด B ตั้งงบ 4 แบบฟอร์ม (happy path)
3. ชุด C กติกาตั้งงบที่ต้องกันได้ (negative)
4. ชุด D ใช้งบ PR / PO / บิล และสูตรคงเหลือ
5. ชุด E จับคู่มิติงบและกรณีขอบ
6. ชุด F สรุปผล Dashboard / รายงาน

## 8. ชุดทดสอบ

สัญลักษณ์ความสำคัญ: **P1** ต้องผ่าน · **P2** ควรผ่าน

### ชุด A — ข้อมูลหลักและเมนู

| รหัส | ความสำคัญ | สิ่งที่ทำ | ผลที่ต้องเห็น |
|---|---|---|---|
| A01 | P1 | เข้าเมนูคำของบหน่วยงาน | เห็นแค่ 4 แบบฟอร์ม ตามชื่อที่กำหนด ไม่มีใบคอม / ต่ำกว่าแสน |
| A02 | P1 | เปิดแบบฟอร์มตั้งงบวัสดุ สร้างใหม่ | หน้าจอเป็นงบวัสดุ มีที่กรอกรายละเอียดสินค้า |
| A03 | P1 | เปิดแบบฟอร์มครุภัณฑ์ / ก่อสร้าง / โครงการ | แต่ละใบแสดงหน้าจอคนละชุด ไม่ปนแท็บวัสดุ |
| A04 | P1 | ตรวจแหล่งเงิน | เลือกได้ เช่น เงินงบประมาณ เงินบำรุง UC เงินบริจาค งบลงทุน |
| A05 | P1 | ตรวจแผนประจำปี | มีเอกสารแผนของปีที่ทดสอบ และระบุช่วงวันที่ |
| A06 | P1 | User หน่วยงานพยายามเข้าเมนูกำหนดค่า master | เข้าไม่ได้ หรือเห็นได้อ่านอย่างเดียวตามสิทธิ์ |
| A07 | P2 | User งานงบเข้าเมนูกำหนดค่า | แก้แหล่งเงิน แบบฟอร์ม กลุ่มวัสดุได้ |

### ชุด B — ตั้งงบ Happy path (ทำครบ 4 แบบฟอร์ม)

ใช้หน่วยงานและแหล่งเงินเดียวกันทั้งชุด เพื่อเทียบรายงานได้

| รหัส | ความสำคัญ | สิ่งที่ทำ | ผลที่ต้องเห็น |
|---|---|---|---|
| B01 | P1 | หน่วยงานสร้างคำของบวัสดุ กรอกเหตุผล รายการ และรายละเอียดสินค้า แล้วส่ง | สถานะเป็น Submitted to Budget Unit |
| B02 | P1 | งานงบรับเรื่อง | สถานะ Received by Budget Unit |
| B03 | P1 | งานงบเริ่มพิจารณา ใส่ยอดจัดสรรครบทุกบรรทัด แล้วน้อยกว่าหรือเท่ากับยอดขอ | บันทึกได้ |
| B04 | P1 | งานงบอนุมัติ | สถานะ Approved และมีบรรทัดงบในแผนประจำปี ยอดใช้จ่าย = ยอดจัดสรร |
| B05 | P1 | ทำ B01–B04 ซ้ำกับแบบฟอร์มครุภัณฑ์ | เข้าแผนในหมวดครุภัณฑ์ |
| B06 | P1 | ทำ B01–B04 ซ้ำกับแบบฟอร์ม ก่อสร้าง | เข้าแผนในหมวดก่อสร้าง |
| B07 | P1 | ทำ B01–B04 ซ้ำกับแบบฟอร์มโครงการ | เข้าแผนในหมวดโครงการ |
| B08 | P2 | เปิดคำขอที่อนุมัติแล้วจากหน่วยงาน | หน่วยงานแก้ไขรายการหลักไม่ได้ |

ข้อมูลตัวอย่างที่แนะนำใน B01

- หน่วยงาน: แผนกที่ตกลง
- แหล่งเงิน: เงินบำรุง
- รายการวัสดุ: อย่างน้อย 1 บรรทัด มียอดขอชัดเจน เช่น 10,000 บาท
- ยอดจัดสรรตอน B03: น้อยกว่ายอดขอ เช่น ขอ 10,000 จัดสรร 8,000 เพื่อพิสูจน์ว่าใช้ได้เท่าจัดสรร

### ชุด C — กติกาตั้งงบที่ต้องกันได้

| รหัส | ความสำคัญ | สิ่งที่ทำ | ผลที่ต้องเห็น |
|---|---|---|---|
| C01 | P1 | สร้างคำของบวัสดุ ไม่ใส่เหตุผล แล้วส่ง | ส่งไม่ได้ ระบบบังคับเหตุผล |
| C02 | P1 | สร้างคำของบวัสดุ มีบรรทัดงบ แต่ไม่มีรายละเอียดสินค้า แล้วส่ง | ส่งไม่ได้ |
| C03 | P1 | งานงบพยายามอนุมัติทั้งที่ยอดจัดสรรบางบรรทัดว่าง | อนุมัติไม่ได้ |
| C04 | P1 | งานงบตีกลับคำขอ | สถานะ Rejected ไม่มีวงเงินเข้าแผน |
| C05 | P1 | หน่วยงานตั้งคำขอที่ถูกตีกลับเป็นร่าง แก้ แล้วส่งใหม่ | ส่งได้ และเข้าคิวงานงบใหม่ |
| C06 | P2 | อนุมัติแล้วดึงกลับเป็นร่าง | บรรทัดงบที่ซิงก์เข้าแผนของคำขอนั้นถูกลบหรือไม่ใช้งาน |

### ชุด D — ใช้งบและสูตรคงเหลือ (เคสแกนหลัก)

เตรียมจาก B04 วงเงินวัสดุจัดสรร 8,000 บาท (หรือยอดจริงที่ใช้ตอนทดสอบ แล้วแทนในสูตร)

| รหัส | ความสำคัญ | สิ่งที่ทำ | ผลที่ต้องเห็น |
|---|---|---|---|
| D01 | P1 | สร้าง PR วัสดุ ให้หน่วยงาน แหล่งเงิน หมวดงบ กลุ่มวัสดุ ตรงกับแผน ยอด 3,000 แล้วกดเช็คงบ | งบเพียงพอ ยังไม่กันเงิน |
| D02 | P1 | ส่งอนุมัติ PR จาก D01 | จองงบ 3,000 คงเหลือ = จัดสรร − 3,000 |
| D03 | P1 | สร้าง PR อีกใบ ยอดเกินคงเหลือ แล้วเช็คงบ | งบไม่เพียงพอ ส่งอนุมัติไม่ได้ |
| D04 | P1 | ยืนยัน PO จาก PR ใน D01 ทั้งจำนวน | ยอดย้ายจากจอง PR เป็นผูกพัน PO คงเหลือเท่าเดิม |
| D05 | P1 | ตั้งเจ้าหนี้และโพสต์บิลตาม PO | ผูกพันลด ใช้จริงเพิ่ม คงเหลือลดตามยอดบิล |
| D06 | P1 | คำนวณมือตามสูตร เทียบกับหน้าจอ | ตัวเลขตรงกัน |
| D07 | P2 | ยกเลิก PR ฉบับร่างที่เคยเช็คงบแล้วแต่ยังไม่ส่ง | ไม่กันเงิน |
| D08 | P2 | ยกเลิก PR ที่จองงบแล้ว | คืนวงเงินจอง |

ตัวอย่างตัวเลขถ้าจัดสรร 8,000

- หลัง D02: จอง 3,000 คงเหลือ 5,000
- หลัง D04: จอง 0 ผูกพัน 3,000 คงเหลือ 5,000
- หลัง D05 บิลครบ 3,000: ใช้จริง 3,000 คงเหลือ 5,000

### ชุด E — จับคู่มิติและกรณีขอบ

| รหัส | ความสำคัญ | สิ่งที่ทำ | ผลที่ต้องเห็น |
|---|---|---|---|
| E01 | P1 | PR เลือกหน่วยงานไม่ตรงแผน | เช็คงบไม่เจอวงเงิน / ไม่พอ |
| E02 | P1 | PR เลือกแหล่งเงินไม่ตรงแผน | เช่นเดียวกัน |
| E03 | P1 | PR วัสดุไม่เลือกกลุ่มวัสดุ | บังคับกรอก หรือจับคู่ไม่เจอ |
| E04 | P2 | PR ครุภัณฑ์ไม่ต้องมีกลุ่มวัสดุ | สร้างและเช็คงบได้โดยไม่บังคับกลุ่มวัสดุ |
| E05 | P2 | ซื้อจากแหล่งเงิน A ทั้งที่มีงบเหลือที่แหล่งเงิน B | ใช้เงิน B ไม่ได้ ต้องตรงแหล่ง |
| E06 | P2 | PO บางส่วนของ PR | จอง PR ลดเฉพาะส่วนที่ PO ครอบคลุม |

### ชุด F — สรุปผลและรายงาน

| รหัส | ความสำคัญ | สิ่งที่ทำ | ผลที่ต้องเห็น |
|---|---|---|---|
| F01 | P1 | เปิด Dashboard ภาพรวมรายจ่ายประจำปี | เห็นยอดจัดสรร ใช้จริง คงเหลือ ของปีที่ทดสอบ |
