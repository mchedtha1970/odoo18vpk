## สิ่งที่ทำไปแล้ว

### ฟอร์มใบสั่งซื้อบนเครื่อง local

อัปเกรดบน Odoo local แล้ว ยังไม่ได้คอมมิตและยังไม่ได้ขึ้น UAT

- ตาราง **ผู้อนุมัติ** (ผู้อนุมัติ ตำแหน่ง ตรวจสอบ ลงนาม) อยู่ในแท็บ **File ใบสั่งซื้อ**  
  โมดูล `vpk_tier_validation` `18.0.1.6.1`
- **เลขที่โครงการ** **ชื่อโครงการ** และ **การจัดซื้อ** อยู่เหนือ **ผู้ขาย**
- **สัญญา** อยู่ใต้ **ส่งถึง** ในคอลัมน์ขวาของส่วนหัว
- **กำหนดการและเงื่อนไขคำสั่งซื้อ** อยู่คู่กับ **ใบขอซื้อ** ในส่วนข้อมูลการจัดซื้อจัดจ้าง แทนที่ที่ว่างของกลุ่มสัญญา  
  โมดูล `vpk_procurement_auto_pr` `18.0.1.38.15`
- ปุ่มในหน้าต่างสร้างใบสั่งซื้อจากใบขอซื้อเปลี่ยนเป็น **สร้างร่างใบสั่งซื้อ**  
  โมดูล `vpk_purchase_contract` `18.0.1.1.35`

ตรวจเลย์เอาต์บนใบสั่งซื้อ P00026 ก่อนถอยรายการ และตรวจข้อความปุ่มจากวิวที่ Odoo ประกอบแล้ว

จากใบขอซื้อ PR6911002 กด **สร้าง PO** แล้วกด **สร้างร่างใบสั่งซื้อ** ได้ใบร่าง **P00027** (id 115) สถานะร่าง ผู้ขายบริษัท ซิลลิค ฟาร์มา จำกัด สัญญา CTR/2026/0010 ยอด 550,000 บาท P00026 ยังเป็นยกเลิก

บนจอกว้าง 1440 พิกเซลของ P00027

- เลขที่โครงการ ชื่อโครงการ และการจัดซื้ออยู่เหนือผู้ขาย
- **ส่งถึง** (คลังกลาง: Receipts) อยู่คอลัมน์ขวา และ **สัญญา** อยู่ถัดลงมาทันที
- **ใบขอซื้อ** กับ **กำหนดการและเงื่อนไขคำสั่งซื้อ** อยู่แถวเดียวกัน
- ตาราง **ผู้อนุมัติ** อยู่ในแท็บ **File ใบสั่งซื้อ**

รอบแรกที่ใส่สัญญาเป็นกลุ่มซ้อนในคอลัมน์ขวา ป้าย **ส่งถึง** หาย เพราะ Odoo 18 มองคอลัมน์นั้นเป็นกลุ่มนอกแล้วไม่สร้างป้ายให้ฟิลด์ เปลี่ยนเป็นเส้นคั่น **สัญญา** ตามด้วยฟิลด์สัญญา ป้ายส่งถึงกลับมา และอัปเกรด `vpk_procurement_auto_pr` เป็น `18.0.1.38.16`

คอมมิต `24700b7` แล้วขึ้น UAT ที่ `https://vpk.24erp.com` อัปเกรด `vpk_tier_validation` `vpk_procurement_auto_pr` `vpk_purchase_contract` และ `vpk_document_studio_onlyoffice` บริการกลับมาทำงาน หน้าเข้าสู่ระบบตอบ 200

### ถอยรายการเพื่อทดสอบตั้งใบสั่งซื้อใหม่

บนเครื่อง local เท่านั้น

- ยกเลิกใบสั่งซื้อ **P00026** (เดิมสถานะยืนยัน ยอด 550,000 บาท สัญญา CTR/2026/0010 แบบไม่จำกัดจำนวน)
- ยกเลิกใบรับสินค้า **WH/IN/00016** ซึ่งยังอยู่ระหว่างรอดำเนินการ ยังไม่รับของ และไม่มีใบแจ้งหนี้
- เปิดใบขอซื้อ **PR6911002** กลับเป็นสถานะอนุมัติ จำนวนที่สั่งซื้อแล้วเป็น 0

จากใบขอซื้อนี้กดสร้างร่างใบสั่งซื้อได้ ใบใหม่จะได้เลขที่ถัดไป P00026 ยังอยู่ในรายการสถานะยกเลิก

### OnlyOffice และงานที่ขึ้น git แล้ว

คอมมิตบน `main` ที่เกี่ยวกับช่วงนี้

- `ea555bd` ย้ายการเติมประเภทสัญญาแบบไม่จำกัดจำนวนไปหลังคอลัมน์ถูกสร้าง เพื่อให้อัปเกรดโมดูลผ่าน
- `1432351` เปิดตัวแก้ไข OnlyOffice ในพื้นที่เนื้อหาของ Odoo
- `1a1453d` ใส่ `customization.logo.visible = false` ในคอนฟิกที่ลงนามแล้ว

บน UAT แก้ทางเดินของ nginx ให้เส้นทางของ Odoo (`/onlyoffice/editor`, `/onlyoffice/file` และอื่น ๆ) ไม่ถูกส่งไป Document Server ทั้งก้อน ให้คอนเทนเนอร์เข้า `vpk.24erp.com` ผ่านเกตเวย์ของโฮสต์ ติดตั้งฟอนต์ TH Sarabun New และ TH SarabunPSK แล้วซ่อนคำว่า ONLYOFFICE ที่แถบหัวของตัวแก้ไข

เครื่อง local ได้การซ่อนชื่อเดียวกันในคอนเทนเนอร์ OnlyOffice และอัปเกรดโมดูลที่เกี่ยวกับโลโก้แล้ว

## สิ่งที่ยังค้าง

- ชื่อหน้าต่างของวิซาร์ดยังเป็น **สร้างใบขอเสนอราคา** เปลี่ยนเฉพาะปุ่มด้านล่างเป็น **สร้างร่างใบสั่งซื้อ**
- ยังไม่ได้ยืนยัน P00027 รับของ หรือปิดใบ ใบนี้เป็นร่างสำหรับเดิน flow ต่อ
- การซ่อนชื่อ OnlyOffice ฟอนต์ไทย และ `--add-host` ยังอยู่ในเลเยอร์ของคอนเทนเนอร์ปัจจุบัน ขั้นตอนสร้างซ้ำอยู่ด้านล่าง

## ปัญหาที่เจอ

- แฟล็ก `logo.visible = false` ถึงตัวแก้ไขแล้ว แต่ Document Server 8.3 ยังวาดคำว่า ONLYOFFICE จากสไตล์ชีตที่เบราว์เซอร์แคชไว้หนึ่งปี ต้องซ่อน `#header-logo` แล้วเปลี่ยน cache tag เป็น `vpkhidelogo1` จึงหาย
- คอนเทนเนอร์ OnlyOffice ต่อ `203.150.191.161:443` ไม่ถึง (`EHOSTUNREACH`) การแก้ไฟล์ hosts ในคอนเทนเนอร์หายเมื่อรีสตาร์ต ต้องใส่ `--add-host` ตอน `docker run`
- nginx ส่งทุกอย่างใต้ `/onlyoffice/` ไป Document Server ทำให้ `get_config` และไฟล์ของ Odoo ได้ 404 จนแยกเส้นทางด้วย regex
- เทมเพลต OWL ของแอ็กชันทางการเป็นหน้า HTML เต็มใบ ซ้อนใน Odoo แล้วพื้นที่เนื้อหาว่าง ต้องทับแอ็กชัน `onlyoffice_editor`
- การเปิดใบขอซื้อจากสถานะเสร็จสิ้นกลับเป็นอนุมัติ ไปชนการตรวจลำดับอนุมัติและขอให้บันทึกคณะกรรมการใหม่ ต้องเขียนสถานะด้วยบริบท `vpk_in_auto_confirm`
- ผู้ใช้ทดสอบ `uat.purchase` อ่านโมเดล `purchase.request` ไม่ได้ การตรวจปุ่มจึงใช้วิวที่ประกอบแล้วและผู้ใช้ `uat.procurement`
- กลุ่มซ้อนในคอลัมน์ขวาของฟอร์ม Odoo 18 ทำให้คอลัมน์นั้นเป็นกลุ่มนอก ป้ายอัตโนมัติของ **ส่งถึง** จึงไม่ถูกสร้าง ใช้เส้นคั่นแทนกลุ่มซ้อนแล้วป้ายกลับมา

## ขั้นตอนถัดไป

1. เดิน flow ต่อจากร่าง P00027 บนเครื่อง local เมื่อต้องการทดสอบยืนยัน รับของ และปิดใบ
2. ถ้าต้องการให้ชื่อหน้าต่างตรงกับปุ่ม ให้เปลี่ยนชื่อแอ็กชันของวิซาร์ดจากสร้างใบขอเสนอราคาเป็นสร้างร่างใบสั่งซื้อ

## สร้างคอนเทนเนอร์ OnlyOffice บน UAT ซ้ำ

คอนเทนเนอร์ปัจจุบันชื่อ `vpk-onlyoffice` อิมเมจ `onlyoffice/documentserver:8.3` พอร์ต `127.0.0.1:18080` ไปพอร์ต 80 ในคอนเทนเนอร์ `--shm-size=1g` รีสตาร์ตนอกจากถูกสั่งหยุด และ `--add-host vpk.24erp.com:host-gateway`

อย่าลบคอนเทนเนอร์เก่า `vpk-onlyoffice-old` ค่า JWT อยู่ในไฟล์ env ใต้ `/var/snap/docker/common/` ใช้ไฟล์นั้นตอน `docker run` แล้วลบไฟล์ทิ้ง อย่าก็อปค่าลับลง git หรือเอกสาร

หลังสร้างคอนเทนเนอร์ใหม่ ให้ทำซ้ำสี่อย่างนี้ ไม่เช่นนั้นชื่อ ONLYOFFICE จะกลับมา ฟอนต์ไทยจะหาย และตัวแก้ไขจะโหลดไฟล์ไม่ถึง

1. คง `--add-host vpk.24erp.com:host-gateway` ไว้ตอน `docker run` การเขียน `/etc/hosts` ในคอนเทนเนอร์หายเมื่อรีสตาร์ต
2. ใส่ฟอนต์ TH Sarabun New และ TH SarabunPSK จาก `/var/snap/docker/common/onlyoffice-fonts/` ไปที่ `/usr/share/fonts/truetype/thsarabunnew` และ `/usr/share/fonts/truetype/thsarabun` แล้วรัน `documentserver-generate-allfonts.sh`
3. ต่อท้าย `#header-logo{display:none!important}` ใน `app.css` ของ document spreadsheet presentation และ pdf และในไฟล์ `.gz` ถ้ามี
4. ตั้ง `set $cache_tag "vpkhidelogo1";` ใน `/etc/nginx/includes/ds-cache.conf` แล้ว `nginx -s reload` ไฟล์ต้นทางใต้ `/etc/onlyoffice/documentserver/nginx/` ไม่มีอยู่ การรีสตาร์ต Document Server อาจสร้าง cache tag เดิมกลับมา ต้องตรวจท้าย `app.css` สาธารณะอีกครั้ง

ตรวจสุขภาพที่ `https://vpk.24erp.com/onlyoffice/healthcheck` ต้องได้ค่า true
